Indexing Cleanup: fixing each reason Google gives for not indexing a page

Phan Minh Hoàng

SEO Leader at Forza, 4+ years in SEO and GEO

Published 13/11/2026. 6 min read.

A page that isn't indexed can't rank. This guide walks through each reason in Search Console's Page indexing report: which ones are real errors, which are normal, and in what order to deal with them.

1. Can Google and AI crawlers read your content?

Check this first. If the main content isn't in the HTML the server returns, nothing else you optimise will matter.

Many sites build their content with JavaScript after the page loads (client-side rendering). Googlebot does run JavaScript, but rendering happens in a later step and costs more. AI crawlers are a harder case: according to Vercel's analysis (December 2024), crawlers from OpenAI, Anthropic, Perplexity and Meta download JavaScript files but don't execute them. Only Gemini (which uses Google's infrastructure) and Applebot render JavaScript.

How to check

  1. Open the page and press Ctrl + U to view the source. Search for a sentence from the main content.
  2. Or open DevTools (F12), go to Network, reload, click the first request and look at Response.
  3. In Search Console, run URL Inspection and choose "View crawled page" to see the HTML Google received.

If all you see is an empty shell like this, crawlers can't see the content:

<body>
  <div id="root"></div>
  <script src="/bundle.js"></script>
</body>

How to fix it

  • Move to server-side rendering (SSR) or static generation (SSG) with frameworks such as Next.js, Nuxt, SvelteKit or Astro.
  • Dynamic rendering with tools such as Prerender.io is only a stopgap. Google states it is not a recommended long-term solution.

2. Reading the Page indexing report properly

This report used to be called Index Coverage, with an "Excluded" group. The current version splits URLs into "Indexed" and "Not indexed", with a reason for each.

The most important point: not every reason is an error. Google says several statuses are expected. Before fixing anything, filter the report by sitemap ("All submitted pages") so you only look at URLs you actually want indexed. URLs outside your sitemap that aren't indexed are usually noise.

3. Handling each reason

3.1. Crawled – currently not indexed

Google read the page but decided not to index it for now. Google calls this a common message that doesn't necessarily need attention, since it doesn't index every page on the web.

What to check

  • Does the page add anything beyond pages already indexed, on your site and elsewhere?
  • Does it share the same search intent as another page of yours?
  • Is it an auto-generated page: filters, tags, pagination, internal search results?
  • Is it linked from related pages, and is it in the sitemap?

Google publishes no minimum word count or internal-link count. Counting words won't diagnose anything. The real question is whether the page is worth Google storing another copy of.

SituationAction
Same intent as a stronger pageMerge into the stronger page and 301 redirect
Auto-generated, no search valueAdd noindex, or remove from the sitemap and cut links to it
Valuable but not distinct enoughAdd original information (data, examples, first-hand experience) and links from related pages
Important for revenue (service, product)Improve the content, then request indexing in URL Inspection

3.2. Discovered – currently not indexed

Google knows the URL but hasn't crawled it. Google explains this usually means the crawl was rescheduled to avoid overloading the server. On a small site, a long stay in this status usually means Google doesn't treat the URL as a priority yet.

What to do

  • Link to the URL from pages Google crawls often: the homepage, menus, related articles.
  • List it in the sitemap with an accurate lastmod date.
  • Cut low-value URLs (parameters, tags, filter pages) so crawling focuses on important pages.
  • Check server response time if many URLs sit in this status.

3.3. Not found (404)

Google is clear: a 404 isn't necessarily a problem if the page was removed with no replacement. 404s on some URLs don't lower the rankings of your other pages.

SituationAction
Page moved to a new URL301 redirect to the new URL
Old URL has external backlinks301 to the closest equivalent page
Page removed, no replacementLeave it as 404 or return 410. Both drop the URL from the index; 410 states the removal is permanent
Internal links point to the broken URLFix the internal links; no redirect needed

3.4. Alternate page with proper canonical tag

The page points its canonical to another, indexed page. Google says there's nothing to do. Only check when the chosen canonical is wrong, for example:

  • URLs with and without a trailing slash: /page and /page/.
  • URLs with tracking parameters such as ?utm_source=.
  • An ad landing page duplicating an SEO page.

In those cases, fix the canonical tag and point every internal link straight at the canonical version.

3.5. Excluded by noindex tag

The page carries <meta name="robots" content="noindex">. The only question is whether that was intended.

  • Filter noindexed URLs in Screaming Frog.
  • Cross-check against Search Console performance data and backlinks to find pages that once had traffic or links and were tagged by mistake.
  • For duplicate pages, consider canonical instead of noindex so signals consolidate on the main page.

3.6. Server error (5xx)

When the server keeps returning 5xx errors, Google slows crawling across the whole site. Fix these early.

  • Read the server logs to see which URL groups fail and when.
  • If the errors come from filter or parameter URLs (for example /category/shoes?price=0-999999), fix how those URLs are generated or block crawling of that group.

3.7. Duplicate without user-selected canonical

Google says this isn't an error: it doesn't show duplicate pages, so it picks one. Act only if Google picked the wrong page:

  • Declare a clear canonical on the duplicates.
  • Point internal links at the page you want to keep.
  • If two pages serve the same intent, merge them with a 301 redirect.

5. A monthly cleanup routine

  1. Export the not-indexed URLs, filtered by sitemap.
  2. Start with real errors (5xx, mistaken noindex, 404s on important pages), then important pages stuck in "discovered" or "crawled" but not indexed.
  3. Fix by group, not URL by URL.
  4. Click "Validate fix" in Search Console for each group you've handled.
  5. Watch the indexed-page trend month by month rather than day by day.

Frequently asked questions

How long until a fixed page is indexed again?

There's no fixed time. On a small site it's usually a few days to a few weeks after Google recrawls. Requesting indexing in URL Inspection can speed up the crawl but doesn't guarantee indexing.

Should I delete every page that isn't indexed?

No. Sort them first: merge pages with duplicate intent, noindex auto-generated pages with no value, and improve pages that have value. Mass deletion without sorting easily loses pages with backlinks or past traffic.

Do 404s hurt my rankings?

According to Google, 404s on removed pages don't affect your other pages. Only act when the broken URL is important, has backlinks, or is still linked internally.
