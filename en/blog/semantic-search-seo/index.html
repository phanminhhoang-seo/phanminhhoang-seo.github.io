Semantic search in SEO: optimising for search intent and entities

Phan Minh Hoang. Published 13/11/2026, updated 13/11/2026. 5 min read.

Many sites run into the same problem: pages compete with each other and rankings swing without a clear reason. The cause is usually a site organised around a keyword list, while Google judges pages by search intent and by how entities relate. This guide goes from the concept to applying it on a real site.

1. What is semantic search?

Semantic search is how a search engine understands the meaning of a query and of content, rather than only matching words. Google moved in this direction with the Knowledge Graph (2012) and Hummingbird (2013), then language models such as BERT (2019).

That doesn't make keywords irrelevant. Google still matches words, but combines that with understanding context: "good lunch spots in District 1" and "office lunch places D1" can be read as the same need. For SEO, a page has to answer the need behind the query, not just contain the right words.

2. Start from search intent

Before writing, read the search results page (SERP) for the main query. The type of page Google ranks is the clearest signal of intent.

  • Page types in the top 10: guides, service pages, product pages or videos? If the top 10 is all service pages and you planned a blog post, you've probably picked the wrong page type.
  • People also ask: the follow-up questions searchers care about.
  • Related searches: the next step in the searcher's journey.
  • Modifiers in the query: "what is", "how to", "guide" usually mean informational intent; "price", "quote", "service", "buy" mean commercial intent.

The rule: one core intent per URL. But queries worded differently with the same intent belong on one page. Splitting them into many small pages only creates more pages that compete with each other.

3. Entities and topic clusters

3.1. How is an entity different from a keyword?

A keyword is a string of characters. An entity is an identifiable thing or concept with attributes and relationships to other entities. "Phone" is a keyword; the iPhone 15 Pro Max is an entity, made by Apple, with colours, storage sizes and a release year.

The more clearly a site describes its entities and how they relate, the less work a search engine needs to understand what the site is about.

3.2. Three steps to define a site's entities

  1. Central entity: what the site exists for, what it sells. Example: SEO services.
  2. Attributes of the central entity: price, process, timeline, results, types (technical, content, GEO).
  3. Related entities: concepts searchers need to understand before deciding: entities, schema, internal links, Search Console.

3.3. From entity relationships to topic clusters

Once you have the entities, define how they relate: "is a type of", "is part of", "is used for". Then arrange them into a cluster with one pillar page and supporting articles:

  • Pillar: /semantic-seo-guide/
  • Supporting articles: /entities-in-seo/, /schema-guide/, /semantic-internal-linking/

Each supporting article must answer its own intent. If two answer the same question, merge them.

4. Schema helps machines understand; it isn't a ranking switch

Structured data (schema) describes, in a machine-readable format, who wrote a page, when it was published and which entities it covers. Google uses it to understand content and to show rich results. Schema itself isn't a direct ranking factor.

Note the 2023 changes: FAQ rich results now only appear for well-known, authoritative government and health sites, and HowTo rich results were removed. You can still mark up FAQPage if it matches the visible content, but don't expect a rich result.

  • Article or BlogPosting for articles: author, published date, modified date.
  • BreadcrumbList for pages in a hierarchy.
  • Organization or Person for whoever owns the site.
  • Product, Service, LocalBusiness when the page really is a product, service or place.

The rule: only declare values that are true and visible on the page. No schema beats wrong schema.

5. Semantic internal linking

Internal links tell search engines how pages relate. Anchor text should describe the entity or task the target page covers. Avoid "read more" or "click here", which say nothing about the target.

  • Supporting article to pillar: anchor contains the main entity, e.g. semantic SEO guide.
  • Pillar to supporting article: anchor describes the sub-entity, e.g. what entities mean in SEO.
  • Between supporting articles: only link when the content genuinely continues, e.g. after defining entities you need to mark up entities with schema.

6. A 30-day plan

Days 1–7: research

  • Export every query from Search Console.
  • Group queries by intent.
  • Pick the central entity and 5–10 related entities.

Days 8–14: foundations

  • Write or fix the pillar page.
  • Publish the two most important supporting articles.
  • Align titles and H1s with intent.

Days 15–21: links and schema

  • Review anchor text and replace generic anchors.
  • Add schema that matches each page type.

Days 22–30: expand and measure

  • Publish 3–4 more supporting articles.
  • Compare CTR before and after title changes.
  • Recheck pages that compete with each other.

7. Example: two intents on one page

Situation: the page /semantic-search-in-seo/ gets impressions for both "what is semantic search" (informational) and "semantic seo services" (commercial). Rankings for both groups are unstable.

Fix:

  1. Keep the current page for the informational intent and remove the sales pitch.
  2. Create a separate service page for the commercial intent, with process, case studies and contact details.
  3. Link both ways between the pages with descriptive anchors.
  4. After 4–8 weeks, check in Search Console that each page receives its own group of queries.

8. Measurement

  • Queries per page: a rise means Google sees the page covering the topic more broadly.
  • Average position alongside query count: both improving together is the good signal.
  • CTR: a rise after a title change means the title matches intent better.
  • Competing pages: in Search Console, open Performance, pick a page and look at Queries. Queries from another intent mixed in are a sign to split or merge.

Frequently asked questions

How is semantic search different from traditional keyword optimisation?

Keyword optimisation focuses on whether a page contains the right words. Semantic search focuses on whether the page answers the search intent and clearly describes entities and their relationships. Keywords still matter, but they aren't enough.

How do entities, ontology and taxonomy relate?

Entities are things and concepts (Hanoi, SEO, Google). Ontology describes the relationships between them (Hanoi is the capital of Vietnam). Taxonomy arranges them into a classification tree. Together they shape a topic cluster.

When should one page be split into two?

When a page receives queries from two different intents, or when the top 10 for the query is a different page type from yours. If queries differ only in wording but share an intent, keep them on one page.

Does schema help rankings?

Schema isn't a direct ranking factor. It helps search engines understand content and makes pages eligible for some rich results. Only declare values that are true and visible on the page.
