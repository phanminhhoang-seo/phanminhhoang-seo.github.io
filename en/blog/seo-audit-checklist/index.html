SEO audit checklist: 86 tasks in 9 areas, what to check and what to fix first

Phan Minh Hoàng

SEO and GEO specialist, SEO Leader at Forza

Published 16/11/2026. 13 min read.

In mid-November 2026, Daniel Foley Carter, an SEO with more than 25 years in the trade, posted a list of nearly a hundred tasks on LinkedIn, opening with the joke that SEO is easy. The list is a fair picture of what a proper audit has to cover. I have regrouped it into 9 areas and added what to look at for each task, which tools to use, and which areas to tackle first.

1. Crawling, indexing and URLs

This area answers three questions: can Google get in, does it understand which page is the main version, and is it wasting effort on useless URLs.

  • Set up a full site crawl: use Screaming Frog or Sitebulb, turn on JavaScript rendering if the site is built with JS, and connect the Search Console and GA4 APIs so clicks and sessions sit next to each URL.
  • Custom extraction: pull data the crawler doesn't collect by default with XPath or CSS selectors, such as last-updated date, author name, schema type, price and stock status. The content audit later relies on exactly these columns.
  • Canonical configuration: every page has a canonical pointing to itself or to the correct main version. The canonical URL must return 200, not redirect and not carry noindex.
  • Canonicalised URLs: filter the URLs that point their canonical elsewhere and look for pages that deserve to be indexed but were folded in by mistake. Cross-check with "Duplicate, Google chose different canonical than user" in Search Console.
  • Hreflang: only for multilingual or multi-market sites. Check return links, correct language codes (vi, en, en-AU), and that every hreflang URL returns 200 and is canonical.
  • Directives: robots.txt, meta robots and the X-Robots-Tag HTTP header. Look for conflicts, such as a page blocked in robots.txt that also has noindex: Google can't fetch it, so it never sees the noindex.
  • Index control: put three lists side by side: URLs that can be crawled, URLs in the sitemap and URLs that are indexed. The gaps show whether the site is leaking junk URLs or missing important pages.
  • One version of every URL: https or http, www or not, trailing slash or not. Only one version returns 200 and the rest 301 to it.
  • HTTP status codes: check what the server actually returns, not just what the browser shows. The most common problem is a "not found" page that still returns 200, a soft 404.
  • Internal redirect and error clean-up: internal links pointing to 301, 302, 308, 404 or other 4xx URLs. Update links to point straight at the final URL. Use 301 or 308 for permanent moves and keep 302 for temporary ones.
  • URL parameters: URLs created by sorting, price filters and tracking codes (?sort=, ?utm_source=). Decide per group: index it, canonicalise it to the base page, or keep crawlers out.
  • Faceted navigation: on e-commerce sites, every filter combination can create thousands of URLs. Only open the combinations people actually search for, such as "grey leather sofa", and block the rest from the start.
  • Product and static routes: one product should have one URL that doesn't change with the category the visitor came from (/sofas/abc and /living-room/abc are two URLs for the same page).
  • Crawl stats: Search Console, Settings, Crawl stats. Look at requests per day, response time, error rate and which file types Googlebot spends its effort on.
  • Server logs: the only way to know which URLs bots really fetch and how often. Logs also show whether AI crawlers such as GPTBot and ClaudeBot visit (see types of AI bots).
  • Clean up non-indexed pages: work through each reason in the Page indexing report, including both "Crawled" and "Discovered – currently not indexed". The full method is in indexing cleanup.

2. JavaScript and rendering

On a standard WordPress site this area goes quickly. On React, Vue or Angular sites it is often where the biggest problems are.

  • Raw HTML vs rendered DOM: compare the source (Ctrl + U) with the DOM in DevTools. Main content, title, canonical and internal links should already be in the raw HTML.
  • CSR or SSR: client-side rendering makes Google wait for an extra rendering step, and most AI crawlers don't run JavaScript, so they see nothing.
  • Tech stack: is it a pure SPA, or does it already use SSR or pre-rendering (Next.js, Nuxt, Astro)? This decides the fix, so find out before writing recommendations.
  • Blocked resources: JS, CSS or API files blocked by robots.txt make Google render an incomplete page. Check the page resources that couldn't be loaded in URL Inspection.
  • JS-loaded content: tabs, accordions, "show more" buttons, lazily loaded reviews. Googlebot doesn't click, so content that only appears after a click is effectively invisible to Google.
  • JS buttons and events: Google only follows <a> elements with an href. A div or button that navigates with onclick is not a link to a crawler.
  • Navigation accessibility: are menu links in the HTML, and does the mobile menu carry the same links as desktop?
  • Dynamic content: content that changes by location, cookie or A/B test variant. You need to know which version Googlebot sees.
  • HTML size: since February 2026, Google's documentation states that when crawling for Google Search, Googlebot reads only the first 2 MB of an HTML file (uncompressed) and ignores the rest. Pages that inline large JSON, SVG or base64 images can pass that limit without any warning in Search Console.

3. Speed, layout and security

  • Core Web Vitals: LCP under 2.5 seconds, INP under 200 ms, CLS under 0.1, measured on real-user data (the Core Web Vitals report in Search Console). FCP is only a diagnostic metric. Any checklist that still lists FID is out of date: INP replaced FID in March 2024.
  • Structured data: the right schema type for the right page type, declaring only values you are sure are correct. Wrong schema is worse than none. Test with the Rich Results Test and the Search Console reports.
  • Security and hack spam: check the Security issues report and look for strange pages with a site: search plus common spam terms (casino, pharma, Japanese characters). The Japanese keyword hack, which injects thousands of pages, is still common.
  • Page layout: is the main content in the first screen, and do pop-ups or ads cover it on mobile?
  • UX: how many steps from the landing page to the contact form or cart, and does the form work on a phone?
  • Titles and descriptions for CTR: compare each title with the page's main queries in Search Console, and find rewritten titles, duplicate titles and descriptions that give no reason to click.

4. Internal links

  • Internal link counts: key service or product pages often have fewer links than tag or author pages. Sort by inlinks and it shows straight away.
  • Orphan pages: pages in the sitemap or getting traffic, with no internal links pointing to them.
  • Anchor text: how many links use generic anchors such as "read more" or "click here".
  • Anchors misaligned with queries: an anchor pointing to page A that uses a keyword page B ranks for. It is an easily missed cause of keyword cannibalisation.
  • Link consistency: internal links go straight to the 200, canonical URL, with the right protocol and trailing slash, and no redirects in between.

5. Search Console data

  • Live URL inspection: for key pages, check the HTML Google renders and the canonical it chooses.
  • Last 3 months year on year: compare with the same period last year to remove seasonality, especially in travel, education and gifting.
  • Click and impression trends: rising impressions with falling clicks usually mean lower positions, or a results page that now has AI Overviews or more ads.
  • Brand vs non-brand: filter queries with a regex of the brand name. Growth sometimes comes only from brand searches driven by ads or PR, not from SEO.
  • Segmented analysis: by query group, by folder (/blog/, /products/), by product line or service. Site-wide totals often hide the segment that is falling.
  • Ranking and CTR for lead-value queries: keep a separate list of queries with commercial value so they don't disappear among thousands of informational ones.
  • AI Overviews impact: queries that keep their impressions but lose most of their CTR, especially question-style queries. Search Console has been testing a separate AI report since June 2026 (see this post on the report).
  • Core and spam update impact: mark update dates on the chart and see which page groups dropped first and most.
  • Query counts: the number of queries per page and for the whole site. A slowly falling query count is often an early signal, before clicks drop.
  • Historic notifications: Manual actions, Security issues and older messages. Especially important when you take over a site from another agency.

6. Content

  • Dead and weak content: pages with no clicks in 12 months and almost no impressions. Classify first, act second.
  • Declining content: separate three cases. Position steady but CTR down: the results page changed or the title is weak. Position down: Google rates the page lower or competitors are better. Impressions gone entirely: check whether the page is still indexed.
  • E-E-A-T: who wrote it, do they have real experience with the topic, and does the site have a clear about page and contact details?
  • YMYL: health, finance and legal content is held to a higher standard and needs clearer authors, reviewers and sources.
  • Unique added value: what does the page have that the top 10 results don't: original data, its own photos, experience, real examples?
  • Fact check: are the figures, prices and regulations in the content still correct?
  • Content age: last-updated dates, outdated information, old years still in titles.
  • Sources and editing: does the content cite sources, and is it reviewed before publishing?
  • Compliance by niche: pharmaceuticals, cosmetics, supplements and finance all have rules on how benefits can be described. SEO content has to follow them too.
  • Entities and topics: compare the entities and subtopics a page covers with the pages that rank (see semantic search in SEO).
  • Writing style: is it easy to read, in the brand's voice, from the perspective of someone who has done the work?
  • Duplicate content: within the site (many near-identical pages) and across the web (copied by others, or manufacturer descriptions copied as-is).
  • AI and plagiarism checks: Google doesn't penalise content for using AI, it penalises mass-produced content with no value. Check for plagiarism with Copyscape or a similar tool.
  • DMCA checks: search the Lumen Database for copyright removal requests against the domain. URLs removed this way don't show in Google.

7. Backlinks and domain history

  • Domain history: use the Wayback Machine to see what the domain used to host, whether it was ever a gambling or spam site, and which old pages with backlinks now return 404.
  • Domain link audit: export referring domains from Ahrefs, Semrush or Majestic. Combine at least two sources, as no tool sees everything.
  • Referring domains by traffic: a domain with real organic traffic is worth more than one with a high score and no visitors.
  • Link distribution: do links all land on the homepage, or do they reach service and product pages?
  • Anchor usage: the share of brand, URL and exact-match anchors. Too many exact-match anchors is a sign of bought links.
  • Link theme and context: is the link in a relevant article, in the main content, or in the footer or sidebar of an unrelated site?
  • Link networks: many linking domains on the same IP, with the same design or the same owner.
  • Tiered links: links pointing at the pages that link to you, pushing strength through several layers. This is usually the footprint of an artificial link scheme.
  • Link spam and PBNs: Google's spam policies class these as link spam. You need to know how much the site has and where it came from.
  • Domain consolidations: are old domains 301-redirected to the site still working, and do their links reach the matching pages?
  • External redirect hops: backlinks to old URLs that pass through 2 or 3 redirects before reaching the current page. Cut them to a single hop.
  • Topical Trust Flow: a Majestic metric showing which topics links come from and whether they match the site's industry.
  • Disavow review: check whether an old disavow file is removing good links by mistake. Google says most sites don't need to disavow and it is only worth considering with a manual action or many paid links.

8. Brand and user behaviour

  • Brand trust: what the press, communities and marketplaces say about the business, and whether its details are consistent everywhere.
  • Brand search volume: track it in Google Trends and in Search Console brand queries over time.
  • Brand search sentiment: type the brand name and see whether autocomplete suggests phrases like "scam" or "is it good", and what the first page of results says.
  • Reviews: on Google, marketplaces and social networks. Volume, rating, and whether the business replies.
  • Google Business Profile: categories, opening hours, photos, review replies. Most important for businesses with a shop or office.
  • Behaviour and engagement: engagement rate, engagement time and user paths in GA4. Heatmaps and session recordings in Microsoft Clarity (free) show where people stop and what they click.
  • Declining engagement: a page that keeps its traffic while engagement slowly falls is usually out of date or no longer matches search intent.

9. Strategy after the audit

The audit shows where the site is broken. This final area turns the findings into a plan.

  • Keyword research: by search intent, grouped into clusters, with each cluster mapped to one page.
  • Keyword viability: what type of page the results show and how strong those domains are. Some high-volume keywords are out of reach for the next 6 months.
  • Content output plan: how many posts a month, which cluster first, who writes and who reviews.
  • Content culls and repurposing: merge duplicates with a 301, rewrite declining posts, remove the ones that can't be saved.
  • Brand building through digital PR: articles, interviews and appearances where customers read. It helps both SEO and getting mentioned by AI.
  • Link earning with linkable content: original data, surveys and calculators, the kind of thing others want to cite.

Which areas come first?

A long list doesn't mean doing everything at once. I suggest the order below, because publishing more content while Google can't index the existing pages is wasted effort.

  1. Blockers: hacked site, manual actions, noindex or robots.txt blocking by mistake, 5xx errors, content bots can't read because of JavaScript.
  2. Crawling and indexing: URL versions, canonicals, redirects, parameters, non-indexed pages.
  3. Search Console data: find which page groups are losing traffic before touching content.
  4. Content and internal links: fix declining pages, merge duplicates, point links at key pages.
  5. Backlinks and brand: clear the risks first, then build.
  6. Strategy: plan content and PR from what the audit found.
